# 无状态单页视觉转写

已撤销上一轮本地 OCR 接入：删除工作区 `.runtime` 中的 Pix2Text 环境、模型权重、pip 缓存、源码安装副本与日志，删除 Ultralytics 配置目录、旧运行配置、依赖锁定文件和旧 OCR 验证产物。用户原始提供的 `C:/skills/pix2text-1.1.7/` 工具包未改动。

保留逐文件 Markdown 转写与知识汇总前置检查，更新为：

1. 所有 PDF 渲染为图像，所有图片逐帧处理；支持格式的内嵌图片也进入视觉转写。
2. 每张图片使用新的 Codex 临时会话，不续接、不分叉主会话，仅携带同文件上一页末尾最多 100 个字符。换文件时清空尾文。
3. 每张图片的正文直接写入 `vision/image-NNN/result.md`；每页完成即更新对应来源的 `资料转写/*.md`。主代理仅收到页号、路径和状态。
4. 重跑跳过已完成页；不确定或失败页保持待解决。新路径使用 `vision-v1` 标记，避免复用旧 OCR 转写。
5. 全部文件转写完成后，按源章节理解、复核和浓缩，合并为 `知识内容.md`；后续路径、学习讲义与核心知识卡片以它为核心。

入口为技能 `scripts/convert_materials.py`，使用环境现有 Python。底层 `scripts/vision_page.py` 使用已登录 Codex CLI 的独立 `exec --ephemeral`，关闭无关工具，结果直接写文件。此方式使用服务端视觉模型及账户额度，已移除本地 OCR 与 Tesseract 调用。没有视觉服务时报告实际错误，不退回主对话累积贴图。

单次请求不再携带过去全部页面；累计重复发送历史的 O(N²) 问题得到避免。单页实际 token 数依赖图片尺寸、密度和模型，不能承诺固定 token 数；大页仍可按必要区域单独处理。

## 验证

自动测试包含页尾100字符限制、续跑恢复尾文、换文件清空历史、逐来源保存、不重复追加、全部转写后才允许汇总，以及失败/不确定/证据变更检查。真实样本位于 `验证样本/无状态视觉/`，包括扫描 PDF、有文字层 PDF、独立图片和 Word 内嵌图片。真实调用情况在完成后追加记录。

最终结果：29 项自动测试通过，技能格式校验通过。真实样本 3 文件、4 张页面/图像全部转写完成，日志中的 4 个会话 ID 互不相同；只有 PDF 第二页带入上一页尾文（最多100字符），其他首图为空。安装版重复运行 processed_pages=0，三份 Markdown 哈希不变。23 个技能文件已同步并校验哈希一致，旧 OCR 配置及字节码已删除。

真实 Codex 调用存在固定系统提示开销与网络重试；这里保证历史不随页数累积，不承诺某个固定单页 token 数。视觉转写完成不代替后续知识和教学质量复核。
