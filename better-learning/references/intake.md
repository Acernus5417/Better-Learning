# 需求确认

按“目标和资料范围 → 基础与前置”的顺序进行。已经明确提供的信息直接记录；一次提问集中于当前阶段，避免长问卷。

第一轮了解课程主题、学习目的、要达到的可观察能力，以及考试/截止日期和每周可投入时间（没有时间限制可不填写）。同时盘点已提供文件，列出文件名和可读状态，确认这些是否是本次全部资料，是否还缺教材上下册、附录、课件备注、题目配图或答案。

资料不齐但用户明确授权以当前材料开始时，记录“当前批次为本次范围”，列出已知缺口。用户尚未回答资料是否齐全时，确认状态保持 false；可做文件盘点和技术提取，不进行最终知识覆盖声明或正式课程编排。

## 无文字层资料（扫描件）的范围确认

扫描件没有文字层时，脚本只能给出机械事实：文件名、格式、页数、字节数、`native_text_characters = 0`。这些足够向用户提问，**不足以也不允许由主代理读图推断**。

- 不要为了「看清这份 PDF 覆盖到第几章」而打开页面图。看图是宿主成员的职责；主代理读图会让图像永久占用主对话上下文，且无法撤回。
- 优先直接问用户：是否为节选、是否含某章、有没有配套答案或下册。
- 用户也不确定时，记为「范围待转写阶段核实」，直接进入 `prepare`。`prepare` 只做渲染与单元化，不需要章节内容；范围可在转写完成、按章阅读文本时核实并回填。
- 确需在转写前拿到章节清单时，派一个轻量成员做范围探测，只回「章节标题 + 页码范围」的短清单，主代理不读图。
- `prepare` 的输出会直接列出无文字层来源并给出处理建议（`scanned_sources` / `range_hint`），照它执行即可。

第二轮询问学过哪些相关课程、能独立完成什么、典型困难和希望补齐的基础。参考目录识别关键前置，必要时提供 2–5 道诊断题，覆盖真正影响路径的基础。用户不愿测试时记录“基础未验证”，采取保守补学路线；这是用户选择，不能假造答题证据。

`学习需求.md` 记录：

- 课程名称、语言、学习目标（每项给可验证行为）、考核要求、时间预算。
- 收到的资料清单入口、资料范围确认的用户原意及日期、缺失项。
- 已学基础、自评、诊断题及实际回答、已证实能力、未知或薄弱前置。
- 补学策略、用户明确偏好、本次范围和未确认事项。

在进度中分别更新 `confirmations.goal`、`confirmations.materials`、`confirmations.baseline`。baseline 表示已与用户确认基础处理方式，不表示用户已掌握所有前置知识。

没有输入教材的情况下，不生成虚构课程。创建空目录、模板不等于完成知识阅读或教学产物。
