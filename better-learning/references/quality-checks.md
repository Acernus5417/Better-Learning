# 质量验收

```text
python SKILL/scripts/validate_package.py --course COURSE --mode staged
python SKILL/scripts/validate_package.py --course COURSE --mode final
python SKILL/scripts/validate_package.py --course COURSE --mode packaged
```

模式固定为 `legacy-report|staged|final|packaged`，默认 `final`；v2 严格模式不接受 heading 锚点与裸文件目标。脚本生成 `_工作区/结构检查.json`（packaged 模式生成 `_工作区/打包检查.json`），退出码 0 表示结构检查通过，1 表示存在问题，2 表示无法执行。错误行统一带错误码，便于按层定位：`[CODE] file[:line] message`。模型将实际结果和内容复核写入 `质量报告.md`，不能用“脚本通过”代替教学质量证明。

`final` 通过时会写 `_工作区/链接校验报告.json` 快照；`packaged` 用它核对交付文件与保留数据（目标是否仍能解析、块是否仍唯一），中间产物已被清理不影响判定，但交付文件内容与快照不一致会报 `STALE_MANIFEST`。

v2 的分层校验顺序：结构（边界/锚点/唯一块）→ 物理落点与 canonical 解析 → 链接形态与 manifest 授权 → 类型矩阵与 subtype 白名单 → 权限（KP/SRC 出边、载荷豁免）→ 图（DEP 无环、闭环/自环）→ 投影（关系区 observed == expected）→ 跨实体引用与来源保真。

先运行 convert_materials.py 的 check，再进行课程结构验收。所有来源应有按原顺序合成的 agent-v1 转写；源、资源、单元正文及总文件哈希有效。转写任务.json 与计划投影一致，没有活动租约、遗漏单元或未经处理的 failed/unresolved。non_teaching/duplicate 有具体理由和证据，不能用于排除难辨认教学内容。

探针只有实际看图、正确转写随机图内容并落盘才通过；成员自报成功不能代替落盘检查。主代理**在任何阶段都不看图**（含质量复核）、不接收正文；复核需要看图时交独立成员针对指定内容检查，只回短状态并保存证据。正常流程不强制额外区域笔记，提交了区域证据就须真实有效。

来源完整性门优先于示例格式：虽然 BL-PAGE 支持 unresolved，正式合成仍必须全来源已完成或明确排除。未核实只是不阻止同批后续页，不代表允许汇总。报告额度问题必须引用实际错误，不能根据 PDF 没有文字层推断额度；不设置人为短段写作要求。

## 分章检查

- 当前章知识条目均有讲义去向，定义、条件、边界、关键推理与来源未在浓缩时丢失。
- 前置已在包内讲清或明确给出实际入口；同章概念按先修顺序讲解。
- 每条目标对应题目，题目只考已教内容；例题和自测答案独立，过程与结论复核。
- 公式符号、单位和条件一致，关键转写字符由成员回看对应图像；图表意义进入正文。
- 学生知道是否过关、错因是什么、下一步回看何处。

## 最终结构检查

脚本检查资料哈希、每个来源单元的覆盖状态、所引用证据文件、知识 ID 和来源引用、教学映射、依赖循环及跨章次序、核心卡片映射、内部文件及锚点链接，以及知识汇编是否与分片一致。数学语法、阅读器实际折叠效果、概念正确性和章节内语义顺序必须另行检查。

结构检查通过后再运行 `package` 收尾（先 `--dry-run` 预览）。打包删除 `_工作区/讲义尝试/`、`_工作区/转写尝试/`、`_工作区/派发提示/`、`_工作区/提取内容/`，并把报告类 Markdown 归入 `课程文档/`；它自身要求无活动租约且全部单元已合成，因此同时充当"转写确已收尾"的机械证明。打包后 `check` 直接返回通过（结构检查结果已存入 `_工作区/结构检查.json`），不要在此之后重复运行 `assemble`。详见 [交付结构](delivery-layout.md)。

最终人工式内容复核还包括：

1. 对照全部来源范围确认没有漏章、附录、图表、题目或答案；duplicate 有实际合并去向，non_teaching 理由合理。
2. 知识库保留全部独立内容；主修/选学分支可覆盖所有知识，不能只写最重要部分。
3. 卡片来自知识库并与已核查讲义一致，没有只在卡片里出现的必需知识。
4. `开始学习.md` 提供真实起点，`学习反馈.md` 保留用户记录，所引用产物均存在。
5. 使用目标阅读器或已有渲染工具抽查公式、复杂表格、图示、答案隔离；未渲染时明确“仅检查源码，未验证实际渲染”。

## 质量报告格式

写明状态（完整 / 受限 / 未完成）、源文件和单元总数、已覆盖/重复/非教学/未解决数量、已完成章节和核心卡片数量、结构检查结果、内容复核范围、渲染验证情况及未解决问题。未解决项指向具体来源位置、影响和下一步。

关键不可读内容、未完成讲义、未补齐的必要前置、错误答案或断链都不能在报告中藏起。用户明确要求部分交付时可交付并标注范围，但保持整体未完成状态和恢复入口。

知识库前置检查：正式写作前必须通过 assemble_knowledge.py --check；用户授权 AI 补全同样必须先形成知识内容.md。能力失败必须报告并建议换模型，不能以目录编写冒充原文。

新课程还检查 WikiLink 目标、稳定块唯一性、类型矩阵与 subtype、关系投影、KP/SRC 出边约束、讲义 commit 和输入快照、核心卡片输入新鲜度。源码或原教材中的链接示例不被当成系统链接；代码块不重写。只有“已登记外壳 + 校验通过载荷哈希”的来源载荷才豁免链接扫描，Agent 自述的豁免一律不算。结构通过仍不证明所有教学解释正确；教学语义复核与图谱验收两条线都不能省。
