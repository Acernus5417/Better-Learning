# better-learning

**把一堆教材，变成一套能自己学下去的课程。**

面向大学生的自学课程生成 Skill：将教材、PDF（含扫描件）、电子书、课件和题库，整理为包含**学习路径、逐章讲义、练习与答案、核心知识卡片、知识链接**的 Markdown 课程文件包。

围绕你的学习目标与已有基础，回答三个问题：**先学什么、怎么学懂、怎样知道自己真的会了。**

项目将教学规范、子 Agent 分工、文件台账和校验脚本组合成一套可执行流程，让生成过程有记录、结果有来源、遗漏有检查入口。

## 为什么做这个项目

很多大学生自学时遇到的困难，来自教材与课堂之间没有补齐的那一段：

- 公式给出来了，中间的推导却被一句“显然”带过。
- 前置知识散落在其他章节，读到一半才发现自己缺了基础。
- 教材、老师的课件、习题和答案各放一处，需要不停切换、拼接。
- 看例题觉得会了，换一道题又不知道从哪里开始。
- 考前能背重点，过后却说不清知识之间的联系。

better-learning 想拆掉这些“防自学”门槛：补齐必要解释，理清先修关系，把分散资料组织成可以一步步走通的学习过程。

**让教材里的知识，更容易被一个没有老师在旁边的学生学会。**

## 你会得到什么

| 产物 | 解决的问题 |
| --- | --- |
| 学习路径 | 根据目标和基础安排先后顺序，先补前置，再逐步深入 |
| 逐章学习文档 | 讲清概念、推理、适用条件和边界，包含例题与易错辨析 |
| 自测与答案解析 | 用实际作答检查理解，并给出错因和回看位置 |
| 核心知识卡片 | 集中复习定义、条件、例子、前置与后续关联 |
| 知识内容 | 汇集资料中的独立知识，作为课程编写与核查的依据 |
| 逐文件资料转写 | 每份输入对应一份 Markdown，保留来源定位 |
| 知识链接 | 连接前置知识、相关讲义、核心卡片与练习入口 |
| 学习反馈与质量报告 | 记录卡点、下一步，以及资料覆盖和未解决的问题 |

讲义按“**问题 → 知识 → 解释 → 例题 → 易错点 → 自测 → 答案 → 过关标准 → 来源**”组织，帮助你完成理解、练习、纠错和复习。

## 如何控制生成文件的质量

better-learning 从**资料完整性、知识覆盖、教学结构和文件一致性**四个方面控制质量。其中一部分由脚本检查，另一部分依靠明确的教学规范与内容复核。

### 1. 先验证能读图，再处理资料

正式转写前，以随机测试图检查当前子代理模型是否能实际识图并保存结果。探针未通过就停止任务，并建议更换模型，不靠目录、标题或常识编造教材内容。模型或宿主改变后重新探测；简单探针通过也不保证复杂页面没有识别错误。

### 2. 每份资料、每个单元都有处理记录

输入资料登记文件版本与来源位置，拆分后的单元记录负责人、输出路径和处理状态。子 Agent 返回“完成”后，还要由脚本检查文件是否存在、是否为空，以及输入和输出的哈希是否一致。

出现失败或 `[待核实]` 的单元会保留问题记录；**在转写合成阶段，未解决单元会阻止正式合成与后续知识汇总**。确认是非教学内容或重复内容，也需要留下理由和证据。

哈希用于发现文件变化，不能证明识别出的公式或文字正确。

### 3. 知识要有来源，也要有教学去向

整理资料时，为知识条目记录来源、所属章节、前置依赖和对应讲义；覆盖台账记录每个来源单元的处理去向。核心卡片从同一份知识库抽取，并关联讲义与练习。

**必须先生成并检查完整、非空的 `知识内容.md`，才能编写学习路径、讲义和卡片。** 用户明确要求 AI 补全时也遵循这个顺序，并标明补全内容与未读原件的范围。

各章知识分片由脚本完整拼接为知识库，避免在最终合并时再做一次有损摘要。结构检查会查找缺失的知识映射、无效来源引用、依赖循环、跨章次序问题，以及断开的文件和锚点链接。

这些检查能发现记录中的缺项与矛盾；**原材料中是否还有未被识别的知识，仍需对照资料复核**。

### 4. 用教学规范约束“怎样讲清楚”

[章节规范](better-learning/references/chapter-writing.md)要求讲清前置知识、定义与条件、关键推理、例题思路、易错点、自测答案和未过关时的补学路径。[卡片规范](better-learning/references/core-cards.md)要求核心知识具备可独立复习的解释、例子、条件和关联入口。

例如，一条公式除了表达式，还应解释符号含义、适用条件、使用方法与常见误用。前置知识也需要提供回顾和补学入口，不能只列几个名词。

这些属于 Agent 必须遵循、逐章复核的内容要求。脚本不会仅凭出现了“例题”“答案”等标题，就判定讲义具有教学质量。

### 5. 验收时区分结构通过与内容可信

交付前运行[结构检查](better-learning/scripts/validate_package.py)，再按[质量规范](better-learning/references/quality-checks.md)复核概念、公式、答案、资料覆盖及实际阅读效果。需要回看图片的内容交给独立成员核查并保存证据。

`质量报告.md` 应说明已检查的范围、未解决的问题和交付状态。结构检查通过不代表数学推导一定正确，也不代表学生已经掌握。**本项目提供的是可追踪、可检查、可返工的质量控制过程，不能保证模型输出零错误。**

转写调度进一步限制资源消耗：可靠文本直接保存，普通视觉任务默认最多5页/成员，疑难页升级单页 overview/tiles 精读，默认并发4并按批次派发（本批全部收集完才开下一批，批内不补位）；主代理只转发任务路径。每次尝试有独立暂存目录和真实 Agent ID，验证通过才提交正式结果，失败有限重试。来源未变时复用提取缓存，最终校验在一次命令内复用哈希与转写解析结果，不降低覆盖检查要求。Office 原生图表等若没有完整页面渲染，会明确阻塞并要求补充渲染或 PDF，避免静默漏读。

## 和纯提示词工程有什么区别？

better-learning 本身也使用提示词工程：教学规范、任务边界与输出要求，都需要通过指令让模型执行。它进一步加入了**文件化的中间结果、确定性的脚本检查，以及由台账驱动的任务调度**。

下面对比的是“只提交一条课程生成提示词、没有另建处理流程”的使用方式：

| 方面 | 单条提示词直接生成 | better-learning |
| --- | --- | --- |
| 资料处理 | 在当前对话中读取资料并生成回答 | 先拆分单元，由独立子 Agent 分批转写、落盘，再进入知识整理 |
| 完成依据 | 主要查看模型回复和最终正文 | 对照单元台账、实际文件、哈希与覆盖记录 |
| 长资料与中断 | 需要另外设计分段、保存和恢复方法 | 提供批次隔离、单元保存和未完成项重派流程 |
| 教学要求 | 依赖本次提示词中的要求 | 按阶段加载章节、路径与卡片规范，使用配套模板 |
| 多文件一致性 | 需要自行检查课程文件之间的关系 | 用知识 ID、来源引用和链接建立关联，并执行结构检查 |
| 错误处理 | 继续追问或重新生成相关内容 | 定位到具体来源、单元或章节，修订后重新校验 |

例如，扫描教材中有一页公式无法辨认时，成员应在该页标记 `[待核实]` 并保存。调度器仍可处理其他页面，但会保留该页的问题状态，等待复核后再通过合成检查。

**它的价值在于把长篇课程生成组织成可执行、可恢复、可检查的工作流程。** 知识理解与讲解质量仍取决于模型能力、材料质量和内容复核。

## 适合怎样使用

- **从零自学一门大学课程**：提供教材和已有基础，建立完整学习路线。
- **跟不上课堂进度**：结合教材与课件，找出前置缺口，补上必要解释。
- **准备期末考试**：结合题库梳理知识和题型，同时保留适用条件与解题依据。
- **整理长期知识库**：把学过的内容沉淀为可以继续编辑、链接和复习的 Markdown 文件。

## 工作流程

1. **确认目标与资料范围**：明确要学到什么程度，并确认收到的文件是否齐全。
2. **了解基础与前置知识**：记录已掌握、薄弱和未知内容，用于后续课程编排。
3. **拆分并转写资料**：机械准备页面、文字与图片，由宿主内可写的子 Agent 分批处理，每个单元完成后立即保存。
4. **逐文件合成 Markdown**：校验落盘结果，处理失败与待核实项，再合成每份来源的完整转写。
5. **按章节整理知识**：分章读取、去重和组织，保留独立知识、条件、例外与不同题型的方法，合成知识库。
6. **编排并生成课程**：以知识库为核心，生成学习路径、逐章讲义和核心知识卡片。
7. **验收与交付**：检查覆盖、依赖、答案和链接，整理成便于学习的课程目录。

### 扫描 PDF 怎么处理？

为统一处理页面中的正文、公式和图表，所有 PDF 和图片都走视觉转写路径；Word、PPT 等支持格式中的文字与内嵌图片按原位置拆分处理。

看图与转写交给宿主子 Agent，正文直接写入文件。主代理负责调度，只接收路径、数量和状态，避免把整本教材的图片不断累积在主对话里。

普通视觉页默认每批最多 5 页、并发 4 批（可配置 1–8，受宿主可用槽位限制）。不确定、不可读或机械判定复杂的页面升级为单页精细识图。**隔离单位是批次，调度单位也是批次**：一批同时派发，成员逐个收集，本批全部结束后才派发下一批，批内不补位。批内仍有上下文开销；已完成内容不重复追加。

当前流程不依赖本地 OCR 模型，也不通过额外的外部 CLI 启动转写。

## 快速开始

### 使用条件

- 一个支持 Skill、能创建**可看图且可写文件的子 Agent**的宿主。
- 本地可用的 Python 与文档处理依赖。核心依赖包括 Pillow、pypdfium2；PDF 辅助文本读取使用 pypdf。
- 宿主模型所需的正常登录、权限和可用额度。

目前提供 Codex、CodeBuddy、Claude 的[宿主适配说明](better-learning/references/host-adapter.md)。实际可用性以当前宿主工具和写权限探针为准。

### 安装

下载并解压本仓库，将其中包含 `SKILL.md` 的 **`better-learning/` 文件夹**放入宿主可发现的 Skills 目录，再按宿主方式加载。

核心文档处理依赖可以安装到你供宿主使用的 Python 环境：

```bash
python -m pip install Pillow pypdfium2 pypdf
```

### 开始一次学习任务

在支持相应调用语法的宿主中使用 `$better-learning`，或直接要求它使用此 Skill。例如：

> 使用 better-learning，把我提供的高等数学教材、老师的课件和期末题库，整理成一套可以独立自学的课程。  
> 我的目标是理解核心概念，并能独立完成常见题型。  
> 我学过高中数学，但函数和三角公式比较薄弱。每天能学习 1 小时，计划用 4 周完成。  
> 请先确认资料是否齐全和我的前置知识，再安排学习路径。结果保存为 Markdown，方便放进 Obsidian。

你不必先把所有需求写得很完整，Skill 会先与你确认目标、资料范围和基础。

## Obsidian 友好

课程以 Markdown 文件组织，公式使用 LaTeX，讲义、卡片与前置知识之间建立链接。可以把课程目录放进自己的 Obsidian 笔记库，继续补充课堂笔记、个人理解和错题记录。

优先使用相对文件链接，方便把整套课程一起保存和迁移。无需为了阅读正文先配置专用数据库或自定义笔记系统。

当前核心卡片集中存放在一个 `核心知识点.md` 中，通过索引和锚点定位；**第一版不默认把每个概念拆成一个独立文件**。细粒度跳转、HTML 折叠和具体公式显示仍需在实际阅读器中检查。知识链接的目标是帮助找到关联内容，不承诺自动生成经过语义验证的 Obsidian 知识图谱。

## 第一版的边界

- **需要 Agent 宿主。** 这是一套 Skill 与辅助脚本，依赖宿主的模型、子 Agent 和文件工具。
- **识别结果需要核查。** 模糊扫描、复杂公式、表格和图形关系可能产生错误；无法确认的内容会保留待核实状态。
- **不同格式的支持有边界。** 受保护文件、旧版 Office 格式、部分矢量图片及无法可靠定位的混合内容，可能需要先转换或补充处理。
- **会消耗宿主模型额度。** 不需要另接一套视觉 API key，不代表离线运行或没有调用成本。
- **生成资料不等于已经掌握。** 学习效果仍需要通过独立作答、自测和反馈来检查。

## 并发课程生成与 Obsidian

转写使用独立的结构化结果文件表达 complete / uncertain / unreadable / vision_unavailable，教材原文中的相同字符串不会被误作任务状态。Python 负责台账、优先队列和批次票据，实际成员仍由宿主创建；并发可按宿主空闲容量降低，一批派发完即等待整批收口。转写期间另有一个独立于主代理的看门狗进程，每 1 分 30 秒提醒"检查子agent是否正常工作"并给出静默时长等只读诊断；它只体检、不处置，转写收口后由主代理停止。

知识库与学习路径完成后，讲义由主代理本人按章生成：`lesson_tasks.py prepare` 产出逐章输入包，主代理一次一章分段落盘，`commit` 由脚本装配边界、锚点与关系区并提交。全部讲义 `check` 通过后，主代理逐章提取候选、跨章统一概念与去重，最后生成核心知识点；不派章级或卡片子 Agent。输入快照（含模板哈希）用于发现知识、路径、需求或讲义变化造成的过期产物。

讲义按自然小节边生成边保存，长小节可再分片，不设机械字数限制。每片成功后更新小型回执，脚本按顺序合并为一章；写入失败或成员提前结束时，验证并复用已保存片段，新尝试只续写缺失内容。复用片段受哈希保护，未完成整章不能冒充正式交付，也不会开始生成核心卡片。

新课程使用课程根目录 WikiLink、稳定 K/KP/EX/SRC 块 ID，以及机器维护的实体到路径映射。支持双向关系校验、讲义重命名和打包后的链接重写。原生 Obsidian Graph View 显示文件节点，块链接提供精确跳转；本版不将每个知识点变成独立图节点。

操作说明：[转写调度](better-learning/references/image-first.md)、[章级讲义与卡片](better-learning/references/lesson-pipeline.md)、[Obsidian 链接](better-learning/references/obsidian-links.md)。
